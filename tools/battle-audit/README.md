# Аудит «Битвы экипажей» с телефонами

`check-battle-room.js` поднимает доску (`play.html?grade=8`) и семь телефонов
(`battle.html?room=…`) в headless-DOM и проходит весь путь: комната → заявки →
лобби → старт → ответы → финал.

Интернет в песочнице недоступен, поэтому поднимается **встроенный MQTT-брокер**
поверх подменённого WebSocket: клиент `shared/battle-mqtt.js` кодирует и разбирает
настоящие пакеты MQTT 3.1.1, брокер маршрутизирует топики `pq/b/<CODE>/…`.
Меняется только транспорт — код игры боевой.

```bash
npm i jsdom
node tools/battle-audit/check-battle-room.js
```

Сценарии:

1. **7 телефонов и сбои** — все видны доске, потерянная заявка повторяется сама,
   переподключение не создаёт дубль, опоздавший получает предупреждение и не ломает
   игру, ответы доходят, финал показывает всех по именам.
2. **40 телефонов** — доска видит 40, в игру входят 40 (экипажи 20 / 20), вопрос
   доходит до всех, ответы всех засчитаны.
3. **Резерв** — без MQTT и PeerJS включается локальный режим с предупреждением.
4. **Ничья** — равные очки дают обоим экипажам первое место.
5. **Доска недоступна** — ошибка «Доска не отвечает» и рабочая кнопка «Повторить подключение».

Текущий результат: **38/38**. Описания — `docs/playthrough/lesson43-battle-roster.md`
(надёжность списка) и `docs/playthrough/lesson44-battle-mqtt.md` (MQTT-комната, 40 телефонов).
