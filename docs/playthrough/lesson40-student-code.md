# Урок 40. Почему код ученика стал 5-символьным и как вернули 4

Дата: 25 октября 2026. Запрос: «давай все еще раз посмотрим и проверим. почему код стал из 5 символов».

## Короткий ответ

Код **не генерировался заново** — он остался от прежней игры 8 класса.
Там код собирался как `"P"` + 4 случайных знака, то есть всегда **5 символов**
(`P7X4K`). В единой трилогии генератор выдаёт **4** символа (`K7M2`), но при
первом запуске профиль подхватывал старый код из `localStorage`, если он был
не короче 4 знаков — так и появлялся `P…`.

```
старая игра 8 класса : makePlayerCode() { let code = "P"; ... 4 знака }   → P7X4K (5)
единая трилогия      : makePlayerCode() { ... 4 знака }                    → K7M2  (4)
миграция профиля     : legacyCode.length >= 4 ? legacyCode : generate()    → P7X4K (5) ← вот причина
```

## Что исправлено

| Место | Было | Стало |
| --- | --- | --- |
| `shared/account.js` → `canonicalShortCode()` | — | единый формат: ровно 4 символа; `P7X4K` → `7X4K` |
| Миграция профиля | сохраняла 5–6 символов | всегда 4: `P`-префикс отбрасывается, длинный код обрезается, пустой генерируется |
| Ручной ввод кода | принимал 4–6, сохранял как есть | принимает старый `P7X4K`, сохраняет `7X4K`; в окне только 4 символа |
| Вход по QR/ссылке (`play.html?code=…`) | 4–6 символов | приводится к 4 |
| `shared/storage.js` | сравнение кодов «как есть» | `canonicalStudentCode()` + `sameStudentCode()` |
| Журнал учителя (`rpg-teacher.js`) | `P7X4K` и `7X4K` — разные ученики | один ученик: сравнение терпимо к старому виду |
| Классы и назначения (`rpg-assign.js`, `print-cards.js`) | код сохранялся как ввели | при сохранении и печати приводится к 4 |
| Подсказки в кабинете учителя | примеры `P1234`, `P5678` | `K7M2`, `LBA6`; код результата — в формате `R2-…` |
| Тексты RU/KK/EN | «4–6 символов» | «4 символа» (+ пометка, что старый `P7X4K` тоже подойдёт) |

Старые записи журнала не теряются: совпадение кодов считается по «хвосту»
(`P7X4K` ≡ `7X4K`), поэтому прежние результаты, классы и назначения
по-прежнему находятся.
